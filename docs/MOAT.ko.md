# HealthMes의 해자

> **문서 지위: 소유자 승인 제품 원칙**
>
> 2026-08-04 소유자 결정에 따라 기록한다. 이 문서는
> `docs/OWNER-VISION.ko.md`의 피드백 학습·설명가능성·로컬-first 원칙을
> 제품 데이터 전략으로 구체화한다.

## 한 줄

**HealthMes의 해자는 개인 건강 데이터 자체가 아니라, 그 데이터를 이용해 내린
의사결정과 실제 결과가 장기간 연결된 개인별 실행 그래프다.**

## 핵심 루프

```text
건강·인지 상태 + 일정 + 목표 + 앱 활동 + 상황
                         ↓
                 HealthMes의 판단
                         ↓
             사용자의 승인·수정·거절·무시
                         ↓
                실제 캘린더와 행동 변화
                         ↓
          이후 집중도·스트레스·회복·완료 결과
                         ↓
               다음 판단의 개인별 최적화
```

HealthMes가 장기간 답해야 하는 질문은 다음이다.

> 이 사용자는 어떤 상태와 상황에서 어떤 결정을 내렸고, 실제로 무엇이
> 효과가 있었는가?

## 해자를 구성하는 네 가지 자산

### 1. 개인 의사결정 그래프

단순 건강 기록이나 일정 기록이 아니라 다음 관계를 연결해 축적한다.

- 수면이 부족한 날 어떤 일정을 옮겼는가
- 어떤 사람·회의·업무 이후 스트레스나 집중도가 달라졌는가
- 사용자가 어떤 제안을 승인·수정·거절·무시하는가
- 어떤 시간대와 건강 상태에서 실제 완료율이 높았는가
- 일정 변경 후 건강과 업무 결과가 개선됐는가
- HealthMes의 판단이 틀렸다면 사용자가 무엇을 어떻게 고쳤는가

### 2. 학습되는 실행 권한

```text
초기: 제안 → 사용자 승인 → 실행
중기: 반복적으로 승인된 패턴 학습
장기: 가역적이고 검증된 범위만 제한적으로 자동 실행
```

해자는 자동화 자체가 아니라, 어떤 판단을 어느 수준까지 위임해도 되는지
축적된 신뢰 기록이다. 자동 실행은 높은 신뢰도, 반복 성공, 낮은 위험,
되돌릴 수 있는 행동이라는 조건을 모두 만족할 때만 허용한다.

### 3. 설명가능성과 알림 품질

모든 제안은 입력 데이터, 개인 baseline, 적용 규칙, 고려한 선택지, 실행 결과를
재구성할 수 있어야 한다. 데이터가 부족하면 `insufficient_data`를 반환한다.

HealthMes는 무엇을 말할지만 학습하지 않는다. 승인율·거절률·무시율·응답시간과
방해 평가를 이용해 **언제 말하지 않아야 하는지**도 학습한다.

### 4. 검증된 판단 프로토콜

```text
전문가 지식
  → 실행 가능한 판단 절차
  → 결정론적 계산과 테스트
  → 실제 사용자 결과
  → 실패 사례와 보정
  → 검증된 개인별 프로토콜
```

코드와 프롬프트는 복제할 수 있지만, 실사용에서 검증된 판단 기준과 실패·보정
데이터는 즉시 복제하기 어렵다.

## 반드시 기록할 데이터

제안 하나를 하나의 `InterventionEpisode`로 연결해 다음을 기록해야 한다.

- 제안 당시 건강·인지 상태와 데이터 신뢰도
- 월간·주간 목표, 일정 제약, 앱 활동 맥락
- 제안 내용과 변경 전·후 일정
- 표시 표면: iPhone, Apple Watch, Android, Wear OS, Telegram 등
- 표시 시각, 응답 시각, 응답 지연
- 승인·수정·거절·무시·만료
- 사용자가 수정한 내용과 수정 이유
- 실제 일정 반영 여부와 provider read-back
- 작업 완료 여부, 실제 소요시간
- 제안 전후 집중도·스트레스·회복 변화
- 알림의 유용성·방해 여부
- 판단 오류와 사용자의 보정 이유

## 해자가 아닌 것

- 지원 웨어러블 개수
- 특정 LLM이나 프롬프트
- MCP 사용
- 자동 일정 배치
- 캘린더 연동
- 네이티브 앱·워치·위젯
- 생성형 UI
- 암호화 백업 기능 하나
- 여러 오픈소스 프로젝트를 연결한 코드

이것들은 필요한 제품 기능이지만 경쟁자가 시간과 자본을 투입하면 복제할 수
있다. 특히 오픈소스 제품에서 코드 자체를 해자로 간주하지 않는다.

## 현재 상태

HealthMes에는 목표, 건강 데이터, 인지에너지, 일정 제안, 결정 기록, 사용자
승인·거절, 캘린더 실행을 연결할 구조가 있다. 그러나 장기간의 실제 결과와
사용자 보정 데이터가 충분히 축적되지 않았으므로 **해자의 구조는 있지만 아직
해자 자체는 없다.**

현재 최우선 과제는 기능 수를 늘리는 것이 아니라 다음 루프를 실제 데이터로
반복하는 것이다.

```text
상태 변화 감지
  → 행동 하나 제안
  → 폰·워치에서 3초 안에 결정
  → 승인된 행동 실행
  → 실제 결과 기록
  → 다음 제안 보정
```
